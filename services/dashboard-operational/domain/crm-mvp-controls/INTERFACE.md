# Proposed interface crm-mvp-controls-proposed-v4

This proposal is awaiting Root admission. The central store/IAM adapter is absent. Default OFF. There is no send function; every result carries authorizesSend=false and operational=false. Source base remains 53844c12e00e3dbdcddb633ee8656c11e97ad7a9. Version 4 supersedes the candidate v3 package without modifying its closed receipt.

## Pure controls

Root loads the audience kernel and deliverability policy from the context pins in claim.json. decision.cjs exports createDecision({kernel,deliverability}), returning a synchronous pure decision(input) function. Input supplies now as an integer epoch time. The boundary injects Root's clock. No store or clock callback is used by the pure decision.

Input includes operationId, selection arguments for kernel.select, before selection, campaign, beforeCampaign, guards for kernel.readmit, and authoritative evidence. The actual pinned kernels perform selection, campaign binding, review revision/expiry and send-guard checks. The actual deliverability policy inspects the supplied brand journal; initialState is never used as a runtime fallback. Empty selected audiences cannot reserve. Missing, unknown, expired, malformed or revoked facts close the decision. Bounce veto remains a local requirement; provider suppression is never claimed.

Evidence fields: brand, membersHash, campaignId, campaignVersion, ledgerRevision, revision (positive authoritative evidence revision), observedAt/expiresAt (nonnegative epoch values; current and at most 60 seconds apart), authority=admitted, suspension=clear and exactly one member entry per selected subject. Each member supplies subjectId, recipientRef (owned opaque hash), consent=current, consentRevision>0, capping=clear, cappingRevision>0, bounce=current, authoritative complete policyState and matching policyRevision. Unknown or missing revisions close. Root owns canonical member/recipient mapping, source completeness, IAM, suspension, capping calculations and freshness. These are trusted server inputs; browser booleans and journal hash integrity are not authenticity proofs.

The decision scope binds brand, operationId, distributionId, selectionHash, membersHash, memberCount, campaignId/version, ledgerRevision, evidenceRevision, evidenceHash and earliest evidence/source/guard expiresAt. evidenceHash covers all supplied member veto facts and policy journals. Root must validate these revisions and hashes against its authoritative transaction snapshot. The fixed policy verifier always refuses event admission; policy construction is for journal inspection only.

## Injected adapter

Root injects an admitted adapter with contractVersion='crm-mvp-controls-proposed-v4', inspectOperation, reserveOperation and recordOutcome. create({enabled,kernel,deliverability,adapter,clock}) defaults to disabled. The contract version alone does not admit an adapter; Root must provide native proof and enable it only after review.

Identity is {brand,operationId,attemptId}; this minimal proposal uses the same original UUID for operation and attempt. Root owns issuance and any future extension to multiple attempts. Neither the boundary nor policy creates new identities.

inspectOperation(identity) must query the existing central journal and return the exact brand/operation/attempt-bound record. Missing/absent, lookup failure or unknown are closed. Reserving requires an already durably registered original operation: state=registered, reservationAttempted=false, durable=true, positive revision, receiptHash. Registration and identity issuance belong exclusively to Root; this package does not create them. Existing reserved/uncertain/accepted/rejected_before_send operations are consulted only. Consultation requires durable receiptHash, scoped reservation proof and matching identity. Never substitute another brand's record.

reserveOperation({brand,operationId,attemptId,expectedOperationRevision,evaluate}) must enforce registration CAS and a durable, one-time reservation-attempt fence in Root's journal. Root must preserve that fence across adapter/process restarts; a failed or uncertain attempt cannot be represented as a fresh registered operation. Invoke evaluate(live) exactly once on the current authoritative evidence inside the protected transaction. Atomically compare source, distribution, campaign, ledger, evidence, consent, suspension, bounce and capping revisions; reserve every member and its capacity; and persist the original operation/attempt. Different operations cannot consume the same capacity or reserved member. A concurrent duplicate resolves to the same original journal record without another write or provider action. No automatic reload/re-evaluation loop is supplied here.

Return state=reserved, exact evaluated scope, matching identity, receiptHash and atomic/idempotent/durable/reservation=true only after durable commit. Missing proof, mismatch, no evaluation, repeated evaluation or lost ACK closes admission and returns the original operation/attempt with action=consult_original, newAttemptAllowed=false and automaticReplay=false. Receipt flags do not prove a production transaction: native adapter admission is required separately. A per-instance Set additionally prevents another reserveOperation call for an attempted identity. That Set is explicitly ephemeral; it is not a durable journal or a replacement for the Root fence.

consult(identity) only queries the original record. Root reconciliation must never write another attempt, resend, rearm consumed markers or automatically release an uncertain reservation. Recreating the boundary relies on Root's durable operation/fence, not its ephemeral Set. Synthetic restart tests merely retain synthetic in-memory records and recreate the boundary.

recordOutcome(identity,outcome) records the original attempt's unknown/accepted/rejected_before_send intent through Root. Root authenticates actual outcome evidence, checks reservation ownership, deduplicates and enforces monotonic transitions; accepted/rejected terminal states must not regress. A caller string is not proof of provider success. unknown persists as uncertain with reservation retained. Acknowledgement requires matching identity, durable receiptHash and expected persisted state. Accounting does not reevaluate present-day eligibility, allowing the previous attempt's result to be recorded after consent/brand/suspension/bounce/capping changes. Missing ACK retains original identity and consult-only recovery.

## Integration and rollback

Before any actual outbound action, Root independently rechecks all changing facts at its final provider gate. A reservation or pure result cannot authorize send. No adapter, route, auth, SQL, service, transport, credential, worker or runtime mount is installed by this package.

Root registers the local B1 claim in its central journal, reviews this proposal, implements/admit its adapter and final gate, verifies all A paths against its managed base, runs Node22.23.3 CI and proves positive/negative real flows. These remain pending. Payload tests use synthetic journals/adapters and real pinned pure kernels only; no production atomicity, durability or restart is proved.

Rollback disables the controls integration gate. Preserve operation journals, attempt fences, reservations and consumed markers. Do not delete/rearm them. Root owns all shared mounting, persistence and deployment paths.

## Version 3 additions

The boundary captures brand/operationId/attemptId as own string data fields before any await. It rejects accessors without invoking them, freezes the captured identity and forwards only declared identity fields (plus outcome where applicable). A caller changing its original object while lookup, reservation, consultation or outcome acknowledgement is pending cannot replace the original identity. Query or outcome acknowledgement failures return that captured identity and consult-only instructions.

Reserved receipts must additionally contain reservedMemberCount=scope.memberCount, reservedMembersHash=scope.membersHash and capacityEvidenceHash=scope.evidenceHash, with valid scoped hashes. A partial or mismatched proof closes admission and preserves the original operation for reconciliation. This is a receipt-binding requirement, not a claim that labels establish native atomicity. Root must produce those values from the real all-member/capacity transaction and prove no partial commit. Consultation uses the same completeness checks; it never promotes incomplete receipts into confirmed reservation.

The synthetic adapter now reserves each member separately under a brand/member capacity key inside its synchronous critical section. Tests cover overlapping selections with different member hashes, whole-operation refusal for one member veto, partial receipt rejection and late bounce/consent/suspension/capping/source/campaign/expiry changes. Native central adapter admission and production all-or-nothing reservation remain Root's responsibility.

Two regression tests were first run against the unchanged v2 source copied into v3 staging and failed: mutation of caller identity during lookup, and loss of identity on failed consultation. They pass after the v3 correction. All earlier negative cases remain in the suite. Membership checks in the pure decision use a Set to avoid repeated linear scans of the selected audience.

## Version 4 outcome recovery and structural receipts

Every reservation/outcome receipt now requires a positive operation revision. Scope validation accepts only the closed set of scalar data fields, plain/null-prototype objects, enumerated own data properties and correct string/integer types. It compares field values independently of property insertion order; extra, missing, hidden or symbol keys and accessors are refused. This implements QA finding B1-V2-SCOPE-PROPERTY-ORDER. No JSON.stringify/digest comparison is used to decide scope equivalence. Scope snapshots protect historical values while asynchronous writes are pending.

recordOutcome first queries the authoritative original reservation. Missing/unknown/corrupt registration or incomplete reservation proof never reaches the outcome writer. If the target state is already confirmed, it returns that original receipt without another write. A different target after accepted/rejected_before_send is refused before writing. Present-day eligibility changes do not stop accounting for the previous reserved attempt.

Root must expose outcomeWriteState on the original operation. Only outcomeWriteState=idle permits a new outcome mutation; pending/uncertain/missing closes the mutation. Root's recordOutcome DTO includes expectedOperationRevision from the authoritative lookup. The adapter atomically CASes that revision, authenticates outcome evidence, prevents terminal regression and preserves the historical reservation scope. A confirmed acknowledgement returns the target state, exact prior scope, durable complete reservation receipt, revision=expectedOperationRevision+1 and outcomeWriteState=idle. unknown provider status persists as uncertain; this is distinct from an unconfirmed outcome JOURNAL WRITE.

The boundary allows only one in-flight outcome writer for an original identity. Missing/invalid write ACK retains the ephemeral outcome fence, and subsequent calls only query the same original operation. A lookup failure without a write does not consume an outcome write. A successful persisted uncertain provider result may later receive a separately authenticated final result through Root; duplicate uncertain intents merely query the known state. Root must durably fence uncertain outcome journal writes across process restart, not rely on the boundary's Set. Reconciliation after an uncertain journal write uses the original identity and never repeats the mutation automatically. If a lost ACK actually committed a terminal result, consultation returns that original known result.

The tests now explicitly pre-register only their declared synthetic identities; unknown IDs return absent. Synthetic capacity contention is keyed by brand/member, including overlap across distinct distributions. The test journal, registrations and attempt/outcome fences remain in memory only. They do not prove a production registration, role, schema, crash recovery, transaction or journal write.

Three new outcome regressions first failed against unchanged v3 source copied into v4 staging: repeated writes after unknown ACK, writing without an authoritative original reservation, and writing an already confirmed duplicate outcome. The QA reordered-scope regression and the equivalent outcome-scope case also failed before structural comparison was corrected. All are preserved in the final passing suite. The public QA receipt is referenced by path/hash in DELIVERY; QA's original receipt remains unchanged and its independent reacceptance is pending.
