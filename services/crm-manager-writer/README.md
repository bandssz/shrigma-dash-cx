# Separate CRM manager WRITER broker — inert proposal

Default `CRM_WRITER_ENABLED=false` constructs no PostgreSQL pool, loads no `pg`, refuses RPCs and reports `ready:false`. It refuses PG/token/issuer material while OFF. Explicit CLI startup opens only the HTTP listener; import opens nothing. No installation or activation is performed by this package.

ON requires the exact PostgreSQL destination `comunicacao_postgres:5432/listmonk`, role `crm_manager_writer_service_v1`, its own issuer/namespace UUIDs and distinct BFF/PG secrets delivered at runtime. Corporate domain is exactly `oaristocrata.com`. Four private POST routes are `/internal/v1/crm-writers/{prepare,commit,revoke,status}` and require Host `comunicacao-crm-manager-writer.tazdb8.easypanel.host` plus `CRM-Writer-Provisioner <private token>`. Browser Origin, CORS/preflight, route aliases, arbitrary SQL, extra JSON fields and manager bearers are refused.

Each lease verifies actual connection parameters, starts one transaction, fixes `search_path=pg_catalog`, checks the pinned WRITER catalog/core, own role/owner/ACLs, then calls an independent fresh STATUS to prove the session's active issuer/namespace binding before the requested RPC. Only four fixed SELECT-function statements have bind arguments. Catalog metadata is a fixed read-only pg_catalog query; no direct issuer/key/permissions data query is used. Health is loopback-only and has a closed response without issuer IDs, key counts, credentials or database snapshots. ON health uses READ ONLY and rollback. The catalog core fingerprint is `464d3cac6073dc6f3c42948203aa0d557d7396cefe1d8a5d0968c83896939311`; LOGIN/owner flags are checked separately.

Requests are canonical UTF-8 JSON <=4096 bytes; responses <=8192 bytes, with closed receipt/error/status projections and correlation. Caps are exactly `read_content,draft,validate,submit`, Growth slot `growth-campaign`; `edit_content`, READ caps and other areas cannot be provisioned. Candidate validity is 10 minutes and credential validity 14 days. The bearer stays in the BFF; SQL receives only its digest. Typed SQL errors use HTTP 200 because the existing WRITER client validates their error schema and fingerprint; local transport/admission failures remain generic HTTP errors. STATUS can return historical receipts without extending TTL.

One SQL lease and queue <=2; request/body/query/connection timeouts are bounded. A timed-out in-flight lease remains counted until it actually settles; its socket is destroyed, no retry occurs, and queued work cannot overlap it. Lost ACK is resolved by BFF durable journal/STATUS with the same operation ID. Timeout cannot prove rollback and is not a physical lock-duration guarantee. Shutdown refuses new/queued work and waits the active lease before ending the pool. Logs contain only three fixed generic failure messages, never headers/body/PG causes.

## Build and resource proposal

The package lock retains the reviewed READ package's exact `pg@8.13.1` dependency entries and integrity hashes; only root package identity differs. Docker pins Node22 image digest `43ac6c60b8f89723f746e8a92ce91abd5017e627ce1ddfe4238355d3a30b772c`, uses `npm ci --omit=dev --ignore-scripts`, UID/GID1000 and an OCI revision label. Closed context admits only package.json/package-lock.json/server.cjs/wire.cjs/admission.cjs/Dockerfile. There is no VOLUME and no secret file.

Future service limits: 128MiB memory+swap, 0.25 CPU, PID32, read-only root, ALL caps dropped, no-new-privileges; sole tmpfs `/tmp:rw,nosuid,nodev,noexec,size=16m,mode=1777`; no published PG ports, no source/identity volume. OFF runs without PG material. ON environment is runtime-only and requires separately reviewed role/issuer activation; no values belong in this README, image or source.

The existing shared Easypanel network provides no demonstrated ingress firewall or traffic segregation. A new Traefik HTTPS endpoint still requires the fixed Host/token/schema checks; the fixed PG host, no published PG ports and closed four-RPC application interface are the proven boundary. Explicit TLS=false matches the observed SSL-OFF PG environment and claims no transport encryption. TLS=true requires verified CA/servername/session TLS. PUBLIC legacy function grants and local TRUST residue are unchanged, so this is not database privilege isolation against a stolen service credential. Privileged activation must separately verify the issuer row/domain/admission before enabling the broker; random STATUS proves only that the session is accepted by the pinned function.

## Evidence and remaining gates

Node22 with an external-network-blocking guard: 19 distinct tests, zero fail/skip. These include real public BFF client compatibility, OFF no-pg child, authentication/closed schemas, encoded-secret refusal, timeout/backpressure/shutdown and actual public SQL lifecycle/legacy preservation in disposable PGlite. Pool transports are deliberate fakes. PGlite denies its shared pg_database catalog to the synthetic service role; no catalog grants were added. Catalog fingerprint/drift are checked under its synthetic administrator. This is not SCRAM, native service admission, an image build or deployed health evidence.

Native/OCI proof is a separate proposed hook under `tools/crm-manager-writer-review/broker/`, pending CI. It must create a fresh isolated PG17.10/listmonk SCRAM cluster and actual service login, use real parameters and alias `comunicacao_postgres:5432`, and prove the exact metadata SELECT as that service. The older NOLOGIN fixture on crm_manager_writer_fixture must remain unchanged. Production SQL/LOGIN/issuer/flags/deploy/pilot/send authorization and human acceptance remain pending.

Local/CI synthetic suite: with existing PGlite dependency resolution, `node --test services/crm-manager-writer/server.test.cjs`; `CRM_WRITER_PUBLIC_SOURCE_ROOT` may point only at the public candidate for a private proposal copy. No pg installation, Docker or real network was used locally.
